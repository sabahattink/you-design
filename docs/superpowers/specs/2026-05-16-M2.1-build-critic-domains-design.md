# M2.1 — Build-Phase Critic + Domain Templates (Design Spec)

**Date:** 2026-05-16
**Slice:** M2.1 (of M2)
**Subsystems touched:** 7 (Intent Engine + Critic — full) and 2 (LLM Brain — partial expansion)
**Status:** Draft — pending user review

---

## Context

M1 + multi-provider shipped a workspace where a vague brief becomes an editable HTML site. The intent agent **only** challenges vague answers during the brief-collection phase. Once the user clicks **Approve & build**, the designer agent runs solo with no oversight — it can produce sycophantic copy, drift from intent, violate a11y, ignore domain idioms, and the user never hears about it.

This is exactly the failure mode V0 / Lovable / Bolt have. M2.1 closes the gap.

## Wedge Statement

> An honest critic watches every designer move. It calls out copy that drifts from intent, a11y violations, and domain-specific anti-patterns. It's structured (not free-form text), suggest-only (not blocking), and runs automatically.

This is *the* moment You Design stops being "just another AI generator."

## Demo Definition

> A user finishes the intent quiz with a brief like "SaaS landing for indie devs." They pick **SaaS landing** as the domain (5th slot of the quiz). The designer agent writes the homepage. The moment write_page completes, the critic runs in the background and produces 3 issues: (1) `warning` — hero headline says "Welcome!" which doesn't match the configured emotion "confident, minimal"; (2) `info` — pricing CTA below the fold conflicts with primary action "start free trial"; (3) `critical` — image lacks alt text. Each issue appears as a chat bubble with severity color, plus a "Fix" button that asks the designer to address it. The sidebar shows a count of open issues. The user fixes #1 with one click, ignores #2, and moves on.

## Architecture Decisions (resolved in brainstorm)

| Decision | Choice | Reason |
|----------|--------|--------|
| Critic timing | **Auto after each designer tool call** | No issue slips by; cost is bounded (1 critic call per designer write) |
| Output format | **Structured JSON via tool call** | UI can render severity, jump to element, attach Fix button |
| Behavior | **Suggest only (no blocking)** | Preserves "honest but not annoying"; user keeps flow |
| Model selection | **Same active model as designer** (configurable later) | Avoids model-selection complexity in M2.1 |
| Context sent | **Full current page HTML + intent contract + domain rules + brief change note** | Whole-page issues (e.g. contrast clashes) caught |
| Storage | **Per-page in workspace store** (localStorage) | Survives reload, scoped to project, no DB yet |
| Domain pick | **5th intent quiz slot** | Conversational, natural |
| Domains in M2.1 | **general / saas / e-commerce / healthcare** | Picked by user |
| Fix action | **Routes to designer agent as a follow-up build message** | Reuses existing build loop; one tool call to address |

## Non-Goals

- ❌ Canvas-level element badges / overlays (chat + sidebar drawer is enough for now)
- ❌ "Critic blocks critical issues" mode (M2.2 with a setup toggle)
- ❌ Cross-page consistency check (single-page only; multi-page review later)
- ❌ Separate model for critic (use active model; cost router lives in M2.3)
- ❌ Critic for intent quiz (intent agent's own challenge tool already covers this)
- ❌ Plugin/marketplace domain templates (M6)
- ❌ Auto-fix without user consent

```typescript
export const Severity = z.enum(['critical', 'warning', 'info']);
export type Severity = z.infer<typeof Severity>;

export const CriticIssue = z.object({
  id: z.string(),
  severity: Severity,
  category: z.enum(['intent', 'a11y', 'domain', 'copy', 'craft']),
  message: z.string().min(1),
  elementId: z.string().optional(),  // data-yd-id if pinpointable
  suggestion: z.string().optional(),
  status: z.enum(['open', 'fixed', 'dismissed']).default('open'),
  createdAt: z.string().datetime(),
});
export type CriticIssue = z.infer<typeof CriticIssue>;

export const CriticReport = z.object({
  id: z.string(),
  pagePath: z.string(),
  triggeredBy: z.string(),  // designer action name
  issues: z.array(CriticIssue),
  createdAt: z.string().datetime(),
});
export type CriticReport = z.infer<typeof CriticReport>;
```

### 4. `apps/web/src/lib/chat/critic-agent.ts` (new)

System prompt + single tool definition.

```typescript
export function criticSystemPrompt(
  contract: IntentContract,
  domain: DomainTemplate,
  triggeredBy: string,
): string {
  return `You are the Honest Critic for You Design.

Your job: review the page just written/edited by the designer agent against the
locked intent contract and the domain rules. Find issues, no flattery, no padding.

INTENT CONTRACT:
- Persona: ${contract.persona.role}
- Primary action: ${contract.primaryAction}
- Emotion: ${contract.emotion}
- Domain: ${domain.label}
- Success metric: ${contract.successMetrics[0]?.name ?? '(none specified)'}

DOMAIN RULES:
${domain.criticRules}

UNIVERSAL CHECKS (always apply):
- Copy: no Lorem ipsum, no "Welcome!", no generic CTAs ("Click here", "Learn more")
- a11y: every <img> has meaningful alt, every <input> has a <label>, no <div onclick>, focus order is logical
- Semantic HTML: <main>, <header>, <section>, <nav>, <footer> used where appropriate
- Emotion fit: visual tone (color, weight, spacing) matches the configured emotion
- Intent alignment: the primary action is visible above the fold and visually prominent

TRIGGERING ACTION: ${triggeredBy}

Call \`report_issues\` ONCE with all issues you find. If the page is genuinely
good with no real issues, return an empty array. Do NOT invent issues for the
sake of looking thorough. Be honest about quality.

For each issue:
- severity: 'critical' (a11y violation, intent contract broken, broken link/missing required element),
            'warning' (likely conversion problem, weak copy, missing best practice),
            'info' (style note, minor polish suggestion)
- category: 'intent' | 'a11y' | 'domain' | 'copy' | 'craft'
- message: one sentence, no fluff, no apologies, no emojis
- elementId: data-yd-id of the offending element if you can pinpoint one
- suggestion: a concrete fix, max one sentence, optional`;
}

export const CRITIC_TOOLS = [
  {
    name: 'report_issues',
    description: 'Report all issues found in the page review. Call this once.',
    input_schema: {
      type: 'object',
      properties: {
        issues: {
          type: 'array',
          items: {
            type: 'object',
            properties: {
              severity: { type: 'string', enum: ['critical', 'warning', 'info'] },
              category: {
                type: 'string',
                enum: ['intent', 'a11y', 'domain', 'copy', 'craft'],
              },
              message: { type: 'string' },
              elementId: { type: 'string' },
              suggestion: { type: 'string' },
            },
            required: ['severity', 'category', 'message'],
          },
        },
      },
      required: ['issues'],
    },
  },
];
```

### 5. `apps/web/src/lib/chat/critic-dispatch.ts` (new)

Orchestrates a critic run after a designer tool call.

```typescript
export async function runCritic(
  triggeredBy: string,
  pagePath: string,
  pageHtml: string,
): Promise<CriticReport | null> {
  const state = useWorkspaceStore.getState();
  if (!state.intentContract) return null;
  const activeModel = selectActiveModel(state);
  if (!activeModel) return null;
  const domain = getDomain(state.intentContract.domain);

  const messages = [
    {
      role: 'user' as const,
      content: `Page path: ${pagePath}\n\nCurrent HTML:\n\n${pageHtml}`,
    },
  ];

  let issues: CriticIssue[] = [];
  for await (const ev of streamLlm({
    model: activeModel,
    system: criticSystemPrompt(state.intentContract, domain, triggeredBy),
    messages,
    tools: CRITIC_TOOLS,
  })) {
    if (ev.type === 'tool-call') {
      const part = ev.data as { input?: { issues?: unknown[] } };
      const raw = part.input?.issues ?? [];
      issues = raw.map((r: unknown) => normalizeIssue(r));
    }
  }

  if (issues.length === 0) return null;
  return {
    id: nanoid(),
    pagePath,
    triggeredBy,
    issues,
    createdAt: new Date().toISOString(),
  };
}
```

### 7. `apps/web/src/lib/chat/designer-dispatch.ts` (modified)

After every successful `write_page` / `update_element` / `add_element`, fire critic asynchronously:

```typescript
case 'write_page': {
  // ... existing logic ...
  store.upsertPage(page);
  store.setCurrentPath(path);
  void runAndStoreCritic('write_page', path, finalHtml);
  return { ok: true, note: `Wrote ${path}` };
}
```

Where `runAndStoreCritic` calls `runCritic`, then `store.setCriticRunning(true/false)` and `store.addCriticReport(report)` on completion.

The `void` makes the critic non-blocking — the tool call returns immediately, critic runs in parallel, UI updates when it finishes.

### 14. Fix flow

When user clicks **Fix** on an issue:
1. Find the issue's suggestion (if any) or message.
2. Build a synthetic user message: `"Fix this issue on ${path}: ${message}. Suggested: ${suggestion}. Element: ${elementId}."`
3. Append to `buildMessages` and trigger `sendBuild()` programmatically.
4. After designer completes, mark the issue as `fixed`.

Implemented in `CriticIssueCard`'s Fix button via a callback that calls the same `sendBuild` already in `ChatPanel`. Refactor `sendBuild` out of the component into a hook (`useDesignerSend`) so it can be invoked from anywhere.

## Data Flow

```
User in build phase asks for a page change
   ↓
Designer agent emits write_page / update_element / add_element
   ↓
designer-dispatch applies change to store
   ↓
designer-dispatch fires runCritic(...) in background (void)
   ↓
Critic LLM call runs (same active model, separate system prompt)
   ↓
Critic emits report_issues tool call
   ↓
critic-dispatch normalizes + calls store.addCriticReport
   ↓
UI: ChatPanel renders new CriticBubble (compact summary),
    Sidebar updates CriticBadge count,
    Drawer (if open) gets the new report appended
   ↓
User clicks Fix on an issue
   ↓
Synthetic message appended to buildMessages, sendBuild() runs
   ↓
Designer addresses the issue, returns a tool call
   ↓
Critic re-runs on the updated page (loop)
```

## Open Questions (resolved at implementation, non-blocking)

1. Should critic re-run on every navigation back to a page, or only on edits? (Default: only on edits; navigation just shows existing reports.)
2. How many old reports to keep per page? (Default: keep last 5, truncate older.)
3. Should the Fix message be visible to the user in chat or hidden? (Default: visible as a normal user message — transparent.)
4. Token budget per critic call? (Default: max_output_tokens=2048 — should be plenty for a JSON tool call.)
5. What if critic fails (network error)? (Default: silent skip; designer action still succeeds. Surface in dev tools only.)

## Risks

| Risk | Mitigation |
|------|------------|
| Critic noise — too many false positives | "Don't invent issues" in prompt; empty array is allowed |
| Cost doubles (every designer call has a critic call) | Documented in README; user can pick cheaper model for critic in M2.3 |
| Critic disagrees with intent quiz output | Both agents see the same contract; if disagree, treat as feedback signal |
| LLM ignores JSON schema for report_issues | jsonSchema() + AI SDK validation; if parse fails, log and skip |
| Race: user edits while critic is running | Critic result lands when ready; if page changed in between, store the report anyway (it's still useful) |
| Domain template prompts conflict with designer prompt | Test each domain in isolation; addendums are constrained to "RULES FOR X DOMAIN" sections |
| Healthcare a11y AA requirements affect cost | Documented as opt-in heavy review |
